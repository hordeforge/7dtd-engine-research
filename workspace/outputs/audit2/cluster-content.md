# Audit: signs.md, map-objects.md, npc-dialog.md (content cluster, V3.0.1 dedi IL)

**Verdict:** All headline server-vs-client attributions verified correct against IL; 1 MAJOR (incomplete NavObjectClass requirement-type registry) and 3 MINOR findings; no CRITICAL.

`$ASM` = `/home/maci/.local/share/Steam/steamapps/common/7 Days to Die Dedicated Server/7DaysToDieServer_Data/Managed/Assembly-CSharp.dll`

## Findings

### F1 MAJOR: map-objects.md §5: NavObjectClass RequirementTypes list is 9 of 14 values

**Claim:** "`Init` parses `requirement_type` into `NavObjectClass/RequirementTypes` (`None, CVar, QuestBounds, Tracking, NoTag, InParty, IsAlly, IsPlayer, IsVehicleOwner`)".

**Ground truth:** `mono tools/bin/EnumList.exe "$ASM" e.txt; grep RequirementTypes e.txt` shows the NavObjectClass enum has **14** members:
`None=0, CVar=1, QuestBounds=2, Tracking=3, NoTag=4, InParty=5, IsAlly=6, IsPlayer=7, IsVehicleOwner=8, IsOwner=9, NoActiveQuests=10, MinimumTreasureRadius=11, IsTwitchSpawnedSelf=12, IsTwitchSpawnedOther=13`.
`mono tools/bin/DumpMethod.exe "$ASM" NavObjectClass Init` confirms `Enum.TryParse<NavObjectClass/RequirementTypes>` (so all 14 are parseable from XML), and `mono tools/bin/DumpMethod.exe "$ASM" NavObject IsValidEntity` shows a 13-target `switch` (IL_0064, `sub 1` then `switch`) dispatching non-None cases up to 13, including `spawnByName` matching (IL_0228/IL_0250) for the Twitch cases the doc's own §6 alludes to. A clone implementing marker filtering from this list would miss 5 requirement types.

**Fix:** extend the §5 list with `IsOwner, NoActiveQuests, MinimumTreasureRadius, IsTwitchSpawnedSelf, IsTwitchSpawnedOther` and reconcile with the §6 prose (which already describes spawnByName/treasure behavior the registry list omits).

### F2 MINOR: npc-dialog.md §5: "`NetPackageNPCQuestList` (channel 192)" mislabels a SendPackage range argument

**Claim:** "mirrored to the client by `NetPackageNPCQuestList` (channel 192)".

**Ground truth:** `mono tools/bin/DumpMethod.exe "$ASM" NetPackageNPCQuestList SendQuestPacketsToPlayer` shows `ldc.i4 192` at IL_00F3 as the **7th** argument of `ConnectionManager::SendPackage(NetPackage,Boolean,Int32,Int32,Int32,Nullable<Vector3>,Int32,Boolean)`, whose parameter list (`mono tools/bin/DumpMethod.exe "$ASM" ConnectionManager SendPackage`) names it `_range` (inert here since `_entitiesInRangeOfEntity=-1` and `_entitiesInRangeOfWorldPos=null`; the send targets `_attachedToEntityId=playerEntityID`). `NetPackageNPCQuestList` has no `get_Channel` override (grep of `MethodList` output); `NetPackage::get_Channel` returns 0, and per docs/protocol.md §"Live capture" channels are only 0/1. Calling 192 a "channel" contradicts protocol.md within the same corpus. Same wording exists in buffs.md:73 and vehicles-drones-turrets.md:132 (out of this audit's scope, flagged for a follow-up sweep).

**Fix:** replace "(channel 192)" with "sent to the client attached to the player entity (`SendPackage` `_attachedToEntityId`; the literal 192 is the default `_range` arg, unused here); channel 0".

### F3 MINOR: map-objects.md §8: NetPackageEntityMapMarkerRemove row conflates two removal paths

**Claim (table row):** "Land claim deactivate/destroy, bedroll clear, crate death | server push (remove) | `NetPackageEntityMapMarkerRemove` (`ToClient`), processed by `World.ObjectOnMapRemove` + `NavObjectManager.UnRegister*`".

**Ground truth:** `mono tools/bin/DumpMethod.exe "$ASM" NetPackageEntityMapMarkerRemove ProcessPackage` (20 IL ops, dumped in full) calls **only** `World::ObjectOnMapRemove` (by key or by position); it never touches `NavObjectManager`. Client-side nav-object removal for the crate flows through `NetPackageNavObject` remove (`AIDirectorAirDropComponent::RemoveSupplyCrate -> NetPackageNavObject::Setup(Int32)` per `FindCallers`, and `NetPackageNavObject::ProcessPackage` IL_00AC `UnRegisterNavObjectByEntityID` / IL_00BD `UnRegisterNavObjectByPosition`), and bedroll/land-claim nav objects are unregistered by the local persistent-data hooks. The row's mechanism column merges these into one package.

**Fix:** split the row: MapObject removal via `NetPackageEntityMapMarkerRemove` -> `World.ObjectOnMapRemove`; NavObject removal via `NetPackageNavObject` (remove form) or local persistent-data hooks.

### F4 MINOR: npc-dialog.md §5: offer-pipeline entry points incomplete

**Claim:** "Entry points: `EntityTrader.OnLockedServer` ... and `NetPackageQuestEvent.ProcessPackage`, both calling `SetupActiveQuestsForPlayer`".

**Ground truth:** `mono tools/bin/FindCallers.exe "$ASM" EntityTrader SetupActiveQuestsForPlayer` lists a third caller: `Quest::refreshQuestCompletion` (re-populates offers after a quest completes). Omission only; the two listed callers are real.

**Fix:** add `Quest.refreshQuestCompletion` as the third entry point.
